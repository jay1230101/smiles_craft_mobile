1. How to install (Android)

  1. Download the new APK file (link shared separately on WhatsApp / email). If you still have the previous build installed, the new one will install over it — your login is preserved.
  2. On your Android phone, open Files → Downloads → tap the APK.
  3. If prompted "For your security, your phone isn't allowed to install unknown apps":
    • Tap Settings → enable Allow from this source → go back and tap Install.
  4. After install, find Smile Craft on your home screen and open it.

4. Known limitations (please don't report these)

The following are expected behaviors for this build, not bugs:
  • Confirm appointment in the popover is intentionally greyed out — backend endpoint /confirm-appt hasn't been added yet. Once the backend ships it, the mobile UI will activate automatically.
  • Push notifications — Profile → Preferences lists "Push Notifications" as upcoming; the device-token endpoint isn't on the backend yet, so no system push toasts will appear.
  • Notifications inbox is client-side only. If the user reinstalls the app or signs into a new device, the inbox starts empty. Server-backed persistence is a later enhancement, not part of M3.
  • Demo mode — patient list, appointment list, summary counts, orders catalog, plan of care entries, visit history, and WhatsApp templates are all sample data. Login itself is live. Switching to live data is a one-line flag (not in scope for QA).
  • Tooth field on Orders only appears when the clinic's show_tooth flag is on. The demo clinic has it on, so QA should see this field — if it's missing on a different live clinic, that's expected.
  • Procedure price auto-fill on Orders uses the price stored on the procedure record in the catalog. If a procedure has no default price, the Price field stays empty after picking it — that's expected and the clinician can type the price manually.
  • Future WhatsApp minimum date is tomorrow — same-day reminders are blocked by design (the web has the same rule).
  • Patient swap on Edit — when you swap a patient and save, the calendar should now show the swapped patient on that slot. The original patient is not deleted; the booking just points at someone else.
  • Reports tab is still a "coming soon" placeholder — M4 scope.
  • Billing tab is still a "coming soon" placeholder — M4 scope.
  • App name may show "smilescraft-mobile (Dev)" or similar — normal for non-production builds.

5. What to report

Please report anything that:

  • Causes the app to crash, freeze, or restart.
  • Shows text or images cut off, overlapping, or going off-screen.
  • Has buttons that don't respond when tapped.
  • Visibly diverges from the designer's Figma (colors, spacing, typography).
  • Contains typos or grammar mistakes.
  • Behaves inconsistently between two runs (worked once, didn't work next time).
  • Is confusing or unclear from a user perspective.
